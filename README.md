# Plenitude — Voice-to-Retention
### Turning every contact-centre call into a churn signal · Retail energy (B2C)

> **FE Bar build submission.** An end-to-end, integrated data journey on the
> Databricks Data Intelligence Platform. **All data is synthetic and
> customer-safe** — generated by `data/generate_synthetic_data.py`, no real
> Plenitude / Eni customer data is used.

---

## 1. The outcome (read this first)

**Problem.** Plenitude sells power & gas to ~2.5M B2C customers in a fully
deregulated Italian market where switching supplier takes minutes. Annual churn
runs at **~12%** — roughly **300,000 customers lost per year**. The contact
centre *hears* churn intent every single day ("your bill tripled", "I'll go to
Enel"), but that intent evaporates as unstructured call audio and is never acted
on until the customer has already left.

**What this build does.** It captures that voice signal. Every call transcript is
scored for **sentiment, intent, and switching intent** with the Foundation Model
API, those voice features feed a **churn model**, and the retention team gets a
**ranked call list** — who to call today, why, and how much they're worth —
surfaced in a Databricks App and queryable in natural language via a Genie Room.

**The value (baseline → after).**

| Metric | Baseline | With Voice-to-Retention | Impact |
|---|---|---|---|
| Annual B2C churn | 12.0% | **11.0%** (target −1 pt) | ~25,000 customers retained |
| Retention targeting | react to cancellations | **rank top-decile before they leave** | 3.0× lift over random |
| Annual gross margin | — | **≈ €4.5M protected** | 25,000 × ~€180 margin |
| Retention analyst self-serve | SQL tickets to BI | **ask Genie in Italian** | hours → seconds |

> €4.5M ≈ 25,000 retained customers × ~€180 annual gross margin per customer.
> A conservative, estimable figure — cutting churn by a single point.

## 3. How it works

1. **Lakeflow** (`notebooks/01_ingest_lakeflow.py`) — Auto Loader ingests the five
   landing files to **bronze**, then declarative expectations conform them to
   **silver** (dropping bad rows, enforcing a bill-plausibility contract).
2. **Unity Catalog** (`notebooks/00_setup_unity_catalog.sql`) — one catalog, a
   `raw`/`silver`/`gold` medallion, a managed Volume, `classification=sensitive`
   tags on transcripts, and least-privilege grants (retention team → gold only).
3. **Gen AI** (`notebooks/02_genai_enrichment.py`) — `ai_analyze_sentiment`,
   `ai_classify`, and `ai_query` turn each transcript into sentiment + intent +
   a churn signal + a summary. No model to host, nothing leaves UC.
4. **ML** (`notebooks/03_churn_model.py`) — a gold feature table joins billing
   trend, contract, and the **voice features**; a GradientBoosting model (MLflow-
   tracked, registered to UC) scores every customer into risk bands.
5. **Lakebase** (`notebooks/04_lakebase_serving.py`) — `gold.churn_scores` is
   synced to managed Postgres for low-latency app reads, plus a `retention_actions`
   table the app writes back to.
6. **Genie Room** (`notebooks/05_genie_room.py`, `genie/…json`) — natural-language
   Q&A over gold ("clienti in Lombardia con tariffa variabile che hanno parlato di
   cambio fornitore?").
7. **Databricks App** (`app/app.py`) — the retention cockpit.

## 4. Evidence it actually ran (readable as text)

The pipeline was **executed** and its real output is committed — no screenshots:

- **`evidence/model_run_output.txt`** — full run log.
- **`evidence/model_metrics.json`** — **ROC-AUC 0.765**, PR-AUC 0.546,
  **precision@top-decile 0.677 = 3.04× lift** over the 22.3% synthetic base rate,
  confusion matrix, feature importances.
- **`evidence/query_results.md`** — gold-layer query results (risk bands, top-20
  call list, churn by region, value at risk).
- **`data/output/*.parquet` + `*_sample.csv`** — the generated data and gold tables.

**The headline finding:** the **voice-derived features are the model's top
drivers** — `churn_mentions` (importance 0.30) is #1, ahead of `bill_trend_pct`
(0.13) and `n_retention_calls` (0.11). That is the whole thesis, proven: the
call centre already knows who's about to churn.

Reproduce end-to-end locally in ~30s:
```bash
uv venv --python 3.12 .venv && . .venv/bin/activate
uv pip install numpy pandas scikit-learn pyarrow
python data/generate_synthetic_data.py     # raw synthetic data
python data/run_local_pipeline.py          # enrich → features → model → gold + evidence
streamlit run app/app.py                   # the retention cockpit (parquet fallback)
```

## 5. Decisions & trade-offs

See `docs/DECISIONS.md`. In short: **GradientBoosting over deep learning**
(explainability + small tabular data + the retention team must trust the "why");
**FM API `ai_query` over a bespoke fine-tune** (time-to-value, zero hosting, good
enough on short transcripts); **Lakebase over serving straight from Delta**
(the app needs point-lookups + action write-back, an OLTP job); **synthetic data
over scrubbed real data** (customer-safe by construction, and reproducible).
